Labels are quoted as they appear on screen, in Spanish like the rest of the localization.

1. Post the invoice and click **Enviar a EDI** (only posted documents are sent). The document
   becomes *Procesando*. Once sent, the payment data (payment type, cheque, card, payment
   condition and due dates) and the fiscal data of the *Facturación Electrónica* tab (issuance,
   transaction, presence, receipt ID, contingency, delivery note, self-invoice, transport with
   its vehicles and deliveries, and associated documents) can no longer be changed. The same
   applies while a send is waiting for confirmation (see item 3).
2. The state updates by itself: *Aceptado* with the XML and the KuDE attached, or *Rechazado*
   with the SIFEN messages in *Mensaje EDI*. With the webhook registered, Sifende notifies Odoo
   as soon as SIFEN answers; otherwise, or if a notification is lost, the cron «Sifende:
   verificar estado de documentos» does it every 5 minutes.
3. If the document is *Rechazado* before reaching SIFEN (for example, a missing required
   field), fix the data and click **Reintentar**: it uses a new idempotency key. If it ends in
   *Error* because of a connection or Sifende failure before the document was registered (the
   message says so), **Reintentar** reuses the same key and nothing is duplicated; meanwhile
   the document cannot go back to draft and its data cannot change, so the retry sends exactly
   the same request. If the *Error* is
   a final failure sending to SIFEN, the document already has its CDC and number: **Reintentar**
   does not reissue it and shows the procedure instead. Retry the batch from the Sifende panel
   or ask support; Odoo polls the document every hour and updates it (*Procesando*, then
   *Aceptado*) when it is processed again with the same CDC.
4. In a credit or debit note, choose the *Motivo de emisión* in the *Facturación Electrónica* tab.
   The associated document is filled with the CDC of the original invoice when it has one. In
   a delivery note, also set who is responsible for the issuance and the route kilometres.
5. When a cash invoice or self-invoice is paid by *Cheque* (*Tipo de Pago* in the *Facturación Electrónica* tab),
   fill in the cheque number (digits only, up to 8) and the bank (4 to 20 characters): Sifende
   requires them. With a card, the *Marca de la tarjeta* is required (*Otra* if it is not listed).
6. If SIFEN rejects a document that was already sent (*Rechazado* with a CDC), Sifende does not
   accept that number again, not even with the same data, and **Reintentar** shows the procedure
   instead of sending. With *Contabilidad > Administrador*, open *Facturación Electrónica > Inutilización de números*, create a voiding with the timbrado and the number of the rejected document and
   click **Enviar al SIFEN**. Then click **Restablecer a borrador** and **Cancelar** on the rejected
   document and issue a new one, which takes the next number. Odoo only allows voiding numbers
   without a document or of rejected documents. If Sifende did not answer, **Enviar al SIFEN**
   reuses the same request: meanwhile the timbrado, the range and the reason cannot change. To
   void a different range, delete the voiding and create a new one.
7. To cancel an accepted document, click **Cancelar EDI**. The «Cancelar documento electrónico»
   wizard asks for the reason (sent to SIFEN) and confirms with **Cancelar Documento**. It
   requires *Contabilidad > Facturación* and the window Odoo checks (48 hours for invoices and
   self-invoices, 7 days for notes). Sifende does not accept cancellations in SANDBOX: the
   button is hidden and Odoo warns if it is attempted another way.
8. Once the document is *Aceptado*, **Imprimir** (the button and the reports menu) delivers the
   KuDE generated by Sifende, with the CDC and the QR, instead of the standard Odoo PDF.
   **Enviar** emails the KuDE as Sifende delivered it, plus the signed XML (Odoo downloads them
   from Sifende if needed; if Sifende does not have them yet, it warns and you can retry).
   While the document is not *Aceptado* (draft, processing, rejected or error), **Enviar** warns
   that there is no fiscal document yet, and **Imprimir** still prints the Odoo PDF with a «Sin
   validez fiscal» notice. If the document was *Cancelado*, **Enviar** does not send the KuDE
   and **Imprimir** shows the cancelled notice; the customer portal and the *Imprimir > PDF*
   menu deliver the same, and the original KuDE and XML stay stored for archiving. Automatic or
   batch sending does not email a pro-forma of a document that is not *Aceptado* either: it is
   left unsent with the reason in the chatter. Vendor bills and documents of other EDI providers
   keep the standard Odoo behaviour.
9. In guaraníes, Sifende rounds the total down to a multiple of 50 and requires payments and
   instalments to cover it (the self-invoice payment too): the connector spreads the Odoo amounts proportionally and the last
   instalment absorbs the difference.
10. If Sifende answers that the number is already in use, the document ends in *Error*. Raise
    the timbrado *Número Desde* to the next free number of the expedition point (see
    *Numeración* in the Sifende panel) and click **Renumerar**: the document takes the next
    free number, never one Sifende already reported, and is sent again with **Enviar a EDI**.
11. In a self-invoice, the type and number of the certificate in the *Autofactura* section
    are added as an associated document when posting or sending; there is no need to enter
    them again in *Documentos asociados*. Sifende receives only the type; the number and the
    control code stay in Odoo.
12. Every line needs a product: Sifende takes the code and the NCM from it. In a delivery note,
    *Datos de transporte* only offers transports without a document or of the same document.
13. The document title, the email subject and the PDF name show the fiscal type and number
    (for example, *Nota de Débito 001-001-0000101*). Odoo's internal number (*FE 00000027*) is
    the journal's accounting sequence and is not changed.
14. If Sifende answers that some configuration is missing (taxpayer data, timbrado or an
    expired certificate), the document ends in *Error*, not *Rechazado*: the message says what
    to fix in the Sifende panel; then click **Reintentar**.
15. If Sifende does not answer when cancelling a document or sending a voiding, try again:
    Odoo reuses the same request and the event is not duplicated. *Probar Conexión* warns
    about inactive expedition points, and *Registrar webhook* about a webhook disabled in
    Sifende.
16. If the partner has no department or no city Sifende recognises, invoices and notes are
    issued without the receiver address, because SIFEN rejects an address without a city. The
    delivery note requires it: choose the *Ciudad SIFEN* on the partner.
17. For air transport, each vehicle needs its *Número de vuelo* (6 characters), shown in the
    vehicle list when the *Aéreo* mode is chosen.

The XML and QR preview is not available: Sifende does not generate documents without issuing
them.
